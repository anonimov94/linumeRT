# Bramka G0: checklista użytkownika (koniec kamienia M0)

Model-Author: Claude · sesja 008 · 2026-10-18

Bramka G0 zamyka kamień M0 (repozytorium, CI, IP, LinuxCNC w środowisku agenta, kopia bazowa ekranu,
rdzeń z atrapą). Agenci sprawdzili wszystko poniżej automatycznie. **Ta lista jest dla właściciela**:
potwierdza, że to samo działa u niego ręcznie: w WSL albo w VM-A z Debianem 12.
Wynik wpisz w tabeli na końcu. Nic tutaj nie dotyczy prawdziwej maszyny: NIEZWERYFIKOWANE NA SPRZĘCIE.

Wzorce wyglądu: [`G0/ekran_bazowy.png`](G0/ekran_bazowy.png) (symulator), [`G0/ekran_plant.png`](G0/ekran_plant.png)
(LinuxCNC z wirtualną obrabiarką Plant).

## 1. Przygotowanie (raz)

Wybierz jedno środowisko:

- **WSL (Windows 11, WSLg):** dystrybucja Debian 12 (`wsl --install -d Debian`) albo istniejąca
  `linumeRT-Debian12` (`tools/vm/setup-debian12-wsl.ps1`). Ubuntu 24.04 w WSL też działa (tak testuje Claude
  w sesji 008), ale wynik wiążący jest na Debianie 12.
- **VM-A:** Debian 12 z pulpitem (VirtualBox; skrypty VM powstaną w sesji 025, do tego czasu instalacja ręczna).
- **Linux z podmanem:** [`docs/PLANT_START.md`](../PLANT_START.md) i [`docs/SIM_WSL.md`](../SIM_WSL.md).

W wybranym systemie (terminal Linuksa, nie PowerShell):

- [ ] Klon repozytorium **w systemie plików Linuksa**, nie w `/mnt/c`:
      `git clone https://github.com/anonimov94/linumeRT ~/linumeRT && cd ~/linumeRT`.
      Checkout na dysku Windows (`core.symlinks=false`) zamienia dowiązanie
      `config/sim/linumert_xyz/qtvcp/screens/linumert` w zwykły plik i ekran linumert się nie uruchomi.
- [ ] Zależności i budowa LinuxCNC 2.9 RIP (kilka minut; `sudo` tylko w pierwszym poleceniu):
      `bash tools/ci/build-linuxcnc.sh --install-deps`, potem `bash tools/ci/build-linuxcnc.sh`.
- [ ] Środowisko Pythona: `python3 -m venv --system-site-packages .venv && .venv/bin/python -m pip install -e '.[dev]'`.

## 2. Testy automatyczne u właściciela

- [ ] `make lint test PYTHON=.venv/bin/python`: ruff bez uwag, pytest bez błędów.
- [ ] `make test-c`: testy rdzenia Plant w C bez błędów.
- [ ] `make -C plant/core shared && make test-linuxcnc PYTHON=.venv/bin/python`: wszystkie testy z markerem
      `linuxcnc` zielone (2–6 min). Po przebiegu `pgrep -l -x 'linuxcncsvr|milltask|rtapi_app'` nic nie wypisuje.

## 3. Ekran linumert z symulatorem

```bash
source ~/.cache/linuxcnc-2.9/scripts/rip-environment
linuxcnc config/sim/linumert_xyz/linumert_xyz.ini
```

- [ ] Okno otwiera się bez okna błędu; tytuł zawiera „linumeRT”; wygląd odpowiada `G0/ekran_bazowy.png`
      (na tym etapie to wciąż wygląd QtDragon; własny wygląd w kamieniu M2).
- [ ] E-STOP zwolniony (F1), maszyna włączona (F2), „Home all”: Z, potem X i Y bazują; DRO X 5, Y 5, Z −5.
- [ ] MDI: `G0 X100 Y50 Z-10`, oś dojeżdża, DRO zgodne.
- [ ] MDI: `M3 S1000`: wrzeciono pokazuje 1000 obr/min; `M5` je zatrzymuje.
- [ ] Otwórz program z `config/sim/nc_files/`, uruchom (Cycle Start). Podgląd ścieżki, program kończy się
      na `M2` bez alarmu. Przy `M6` potwierdź okno ręcznej zmiany narzędzia.
- [ ] Zamknięcie okna: LinuxCNC kończy pracę bez „Segmentation fault” w terminalu.

## 4. Ekran z wirtualną obrabiarką Plant (opcjonalnie)

W jednym systemie (Plant na localhost):

```bash
source ~/.cache/linuxcnc-2.9/scripts/rip-environment
make -s -C plant/core shared
T=$(mktemp -d); cp hal/lrt_net.comp hal/lrt_net_proto.h hal/lrt_cia402.comp "$T"/
(cd "$T" && halcompile --install lrt_net.comp && halcompile --install lrt_cia402.comp)
PYTHONPATH=core:plant/server .venv/bin/python -m linumert_plant serve \
  --plant config/plant/linumert_plant_xyz/plant.yaml &
linuxcnc config/plant/linumert_plant_xyz/linumert_plant_xyz.ini
```

- [ ] Wygląd jak `G0/ekran_plant.png`; po F1, F2 i „Home all” osie bazują z losowej pozycji na
      krańcówkach Plant (portal Y synchronicznie).
- [ ] MDI `G1 X100 Y200 Z-20 F3000`: DRO zgodne, bez błędu nadążania.
- [ ] Po zamknięciu LinuxCNC zatrzymaj serwer Plant: `kill %1`.
